```bash
# 1. 本地推代码
git push prod yuanqu-v2.0

# 2. 服务器检出
cd /opt/liqi-saas-v2/app && git fetch origin && git reset --hard origin/yuanqu-v2.0
# 补回不入库配置（见上表），并改 application-local.yaml / .env.prod

# 3. 后端（JDK8 + Maven）
cd backend && mvn -B -pl yudao-module-liqi,yudao-server -am package -DskipTests
systemctl restart liqi-server

# 4. 前端
cd ../frontend && pnpm install --no-frozen-lockfile && pnpm run build:prod
rm -rf /var/www/liqi-admin && cp -r dist-prod /var/www/liqi-admin && chmod -R 755 /var/www/liqi-admin
systemctl reload nginx
```

## 七、注意事项

- 服务器磁盘余量偏紧（约 8.5G），`node_modules` 占 1.1G、后端 jar 约 150M，构建前留意清理
- 后端由 systemd `Restart=always` 守护，且启动脚本内含 `pkill -f yudao-server.jar`，
  **手动 `java -jar` 起的实例会被守护进程杀掉**，改版本必须走 `systemctl restart liqi-server`
- 阿里云 SSH 需固定 `KexAlgorithms=diffie-hellman-group14-sha256`，否则握手卡死

## 八、性能优化（首次上线后补做）

**问题现象**：浏览器打开 `/admin/` 长时间白屏，看似「无法访问」；Nginx 日志可见
`/app-api/liqi/policy/page` 返回 **499**（客户端等不及主动断开）。

**根因**：Nginx **未开启 gzip**。前端产物 30MB / 2042 个 JS 文件，其中**首屏就需加载 77 个文件、
未压缩合计 5.7MB**；实测该服务器外网带宽约 **485 KB/s**，即首屏需约 **11 秒**，表现为白屏。
服务器端本身响应极快（毫秒级），并非服务故障。

**处理**：
1. `/etc/nginx/nginx.conf` 的 `http` 块内开启 gzip（`gzip on` + `gzip_types` 覆盖 js/css/json/svg 等）
2. `/etc/nginx/conf.d/h5-huiqi.conf` 增加 `location ^~ /admin/assets/`，`expires 30d`
   （产物文件名带内容哈希，可安全长缓存；`^~` 保证优先级高于 `/admin/`）

**效果**：

| 项 | 优化前 | 优化后 | 降幅 |
|---|---|---|---|
| 最大 JS 包 | 1550 KB | 499 KB | 68% |
| form-designer | 1108 KB | 342 KB | 70% |
| index.html | 153 KB | 48 KB | 69% |
| **首屏合计** | **5736 KB（约 11s）** | **1648 KB（约 3s）** | **71%** |

> 后续如需进一步提速，可考虑：产物构建开启 brotli、拆分路由懒加载减少首屏包数、
> 或为静态资源接 CDN。当前 3 秒首屏在该带宽下属可接受范围。
